# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Scope

This guidance applies to `src/components/xay-dung-de-thi/quan-ly-de-thi/` — the **"Quản lý đề thi"** (Exam Management) feature: assembling actual exams (manually from the question bank, auto-generated against a saved "ma trận đề" / exam matrix, auto-generated **by AI (Gemini)** straight from "Cấu hình môn học", or as shuffled permutation packages/single-exam variants), listing/searching them, and sending them through a review ("thẩm định/phản biện") workflow.

## Files

- `ExamManagementModule.tsx` — list screen. Two tabs: "Đề gốc" (root exams, `source !== 'ai'`) and "Thẩm định/phản biện đề" (exams with `status pending/'2'`, Trạng thái filter here is **locked/disabled** — always "Chờ thẩm định", cannot be changed). Owns `GET /api/exams` + `GET /api/exams/packages`, batch delete, approve/reject, Word (.doc via hand-rolled RTF, not real .docx) and stub Excel export. "Trạng thái" filter (Đề gốc tab) options: Tất cả (mặc định) / Nháp / Đã thẩm định / Chờ thẩm định / Từ chối. "Chỉnh sửa" action only shown via `canEditExam(row.status)` (hidden once `status` is `'3'`/`'approved'`/`'active'`). Per-row actions: Xem, Chỉnh sửa (conditional), **Sinh đề hoán vị** (opens `ModalSinhDeHoanVi` scoped to that row), "..." dropdown (`getActionMenuItems`). Switches into `ModalDeRiengLe` / `ModalTaoDeTuDong` / `ModalAddGoiDeThiNew` / `ModalSinhDeHoanVi` via local state, not routing.
- `ModalDeRiengLe.tsx` — manual single-exam create/edit ("Đề thi riêng lẻ"). Biggest file; assigns bank questions into 3 fixed structural parts (Phần I single/multiple, Phần II true_false, Phần III short) mirroring the THPT format. Uses `ModalChonCauHoi` both for bulk "Chọn câu hỏi" (`mode='multi'`) and per-question "Đảo câu hỏi tương đương" swap (`mode='single'`).
- `ModalTaoDeTuDong.tsx` — "Thêm mới tự động" wizard with a `Segmented` **nguồn sinh đề** switch at the top choosing between two independent flows (switching resets wizard state back to step 0):
  - **`sourceMode: 'matrix'`** (original flow, 3 steps: "Môn học, Chủ đề & Tiểu mục" → "Ma trận đề" → "Đề tự động"). Loads a saved matrix via `apiGetMatrixConfigDetail` (from `../quan-ly-ma-tran-de/mockData.ts`), builds `RandomSelectCellAPI[]` cells from its `ds_cau_truc`, and calls `bankQuestionApi.randomSelect(...)` to pull matching **already-approved bank questions** per cell — no AI involved here, pure SQL `ORDER BY RAND()`. Saves via `questionIds` linking (no new `Question` rows created).
  - **`sourceMode: 'ai_config'`** (new, 2 steps: "Môn học & Khối lớp" → "Đề tự động (AI sinh)"). Reads "Cấu hình môn học" (`subjectConfigApi.getBySubjectId`) directly — no matrix, no chủ đề/tiểu mục selection — and calls the **real Gemini AI service** (`/api/generate-questions`, same endpoint the Question Bank's AI generator uses) to produce brand-new questions per Phần I/II/III part. Optimized to **1 AI call per part** (not 1 per cognitive level — the schema's own `easyPercent/mediumPercent/hardPercent` mix is used instead of forcing single-level batches), batched at ≤15 questions/call (the AI service's hard cap), and **aborts immediately** on the first failed call (e.g. Gemini quota exhaustion) instead of continuing to burn quota across every remaining part. AI's returned `easy/medium/hard` is mapped to `nhan_biet/thong_hieu/van_dung` (the DB's `cognitive_levels` table currently only has these 3 rows — no "Vận dụng cao"). Saves by creating a bare `Exam` (`POST /api/exams`, no questions) then one `questionApi.create({..., examId})` per question (fuzzy-matches subject/grade/level/type by **name** server-side, avoiding the id-resolution ModalAddGoiDeThiNew never does correctly).
  - Both modes share the final "Đề tự động" step/UI and the same per-question **edit/regenerate** wiring (see `ExamContentDisplay.tsx` below): "Sửa" opens a type-aware edit sub-modal (options+correct radio for `single`, 4 statements+Đúng/Sai toggle for `true_false`, plain textarea for `short`); "Sinh lại" replaces just that one question — in `matrix` mode by picking a different bank question of the same type/level not already used, in `ai_config` mode by calling AI again for exactly 1 question of that type/level/topic. **No swap-count limit** (removed on request) — only a `regeneratingIndex`-based UI lock so only one question regenerates at a time.
  - Bug fixed here (2026-07): the topic-loading `useEffect` used to also filter by `grade_id`, and additionally re-ran (and reset `checkedTopicKeys`) on every `step` change because `step` was in its dependency array — ticking topics then clicking "Tiếp tục" silently wiped the selection before it could ever match a matrix's `don_vi_id`, always showing "không có tiểu mục nào trùng". Now the topic list is filtered **only by `subject_id`** (matching exactly how `CreateMatrixForm.tsx` derives `don_vi_id` when building a matrix) and the effect no longer depends on `step`.
- `ModalSinhDeHoanVi.tsx` — **new**, single-exam-scoped permutation generator ("Sinh hoán vị và tải"), opened from `ExamManagementModule`'s per-row action icon (distinct from `ModalAddGoiDeThiNew`'s toolbar multi-exam flow — both coexist; this one always operates on exactly one already-selected root exam). Flow: fetch the source exam's real questions (`bankQuestionApi.list()` filtered by `examId`) → form (Môn học locked to the source exam's subject; Ma trận đề / Đợt thi are **optional, label-only** dropdowns — see Package model note below; Mã/Tên gói đề thi default to the source exam's own code/name; Mã đề bắt đầu từ; Số lượng đề hoán vị) → "Sinh đề hoán vị" builds an in-memory preview (client-side only, not yet saved) by Fisher-Yates-shuffling **only the `options` array of `single`-type questions** (leaves `true_false`/`short` content untouched — matches the real THPT "mã đề" convention of only reordering Phần I answer choices) — `correctAnswer` needs no recomputation since it stores the correct option's full **text**, not a letter (unlike the old `ModalAddGoiDeThiNew`, which wrongly assumed a letter and does an unnecessary/buggy recompute) → preview shown per-variant via `ExamContentDisplay` tabs, with per-variant "Tải xuống" (RTF-as-.doc) and a "Tải xuống tất cả đề" that zips everything client-side with `jszip`. **"Lưu gói đề" is a separate, explicit step** (preview-only until then) that creates each variant as a real `Exam` (`POST /api/exams`, no questions) + its questions via `questionApi.create({..., examId})` **in parallel** (`Promise.all`, both across variants and across each variant's own questions — sequential awaits against the remote TiDB DB were measured taking up to a minute+ for a handful of questions), then one `POST /api/exams/packages` linking `[sourceExamId, ...newVariantIds]` plus the optional `matrix_id`/`exam_period_id`. Per-variant failures (e.g. a duplicate `exams.code`) are caught individually and reported by code rather than aborting the whole save — but **there is no rollback**: if the final package POST itself fails (e.g. duplicate `packages.code` — the default package code is the source exam's own code, so re-running this flow twice for the same exam without changing it *will* collide), the already-created variant `Exam`/`Question` rows are **not** cleaned up; the error message says so explicitly so the user knows to look for orphaned exams rather than just retrying blindly.
- `ModalAddGoiDeThiNew.tsx` — 2-step wizard to build an exam "package" from the **toolbar** (multi-exam picker, unrelated to `ModalSinhDeHoanVi` above and left untouched): pick existing root exams, client-side shuffle their options into N permutation variants (đề hoán vị, `source:'ai'`), then POST both the new permutation exams and the package. **Still has the broken-schema bug** noted below (kept for reference — `ModalSinhDeHoanVi.tsx` is the fixed reference implementation of the same "create new questions tied to a new exam" problem, using `questionApi.create` instead of `ExamCreate.questions`).
- `ModalChonCauHoi.tsx` — shared question-picker modal (used by `ModalDeRiengLe` only, currently). Takes an already-fetched `questionPool: Question[]` from its parent and does **all filtering client-side** (topic tree, grade, type, level, status, free text) — it does not call `bankQuestionApi` itself, only `topicsApi.list()` for the topic tree.
- `ModalChiTietCauHoi.tsx` — read-only question detail sub-modal, opened from inside `ModalChonCauHoi`.
- `ExamContentDisplay.tsx` — shared renderer for a question list, now actually wired for editing (previously dead code — no caller passed `allowEdit`). Props: `allowEdit`, `onEditQuestion` (new — "Sửa" button), `onReplaceQuestion` ("Sinh lại" button, renamed from "Đổi nhanh"), `onFindSimilar` ("Tìm tương đồng", still unused by any caller), `regeneratingIndex` (replaces the old `swapCounts`/`maxSwaps` — no more artificial regenerate-limit, just a per-index loading/disable state while one question is mid-regenerate). Each action button now only renders if its handler prop is actually passed (previously "Đổi nhanh"/"Tìm tương đồng" always rendered even with no handler wired — inert dead buttons). Also fixed a pre-existing correctness bug: the single-choice "correct answer" highlight compared `q.correctAnswer` against the option **letter** (A/B/C/D), but the real stored convention (confirmed against `quan-ly-nhch/.../manual-create.tsx`) is the option's full **text** — now checks both (`=== opt || === label`) so real data actually highlights correctly.

## Architecture / cross-feature coupling

- **Two disjoint API access patterns coexist in this feature** — don't assume "relative path" is the norm everywhere:
  - Gateway-relative (port 8000, proxied): `ExamManagementModule` (`/api/exams`, `/api/exams/packages`), `ModalAddGoiDeThiNew` (`/api/exams`, `/api/exams/packages`), `ModalTaoDeTuDong`'s save step(s) (`/api/exams`, plus `/api/generate-questions` for `ai_config` mode) and matrix list fetch (`/api/matrix-configs`), `ModalSinhDeHoanVi`'s exam/package creation (`/api/exams`, `/api/exams/packages`).
  - Direct-to-service, hardcoded `http://localhost:8001/...` (bypasses the gateway entirely): everything in `src/services/danhMucApi.ts` (`bankQuestionApi`, `topicsApi`, `subjectCategoryApi`, `gradeLevelApi`, `examPeriodApi`, `subjectConfigApi`, `questionApi`, ...), **and** `ModalDeRiengLe.tsx`'s own create/update calls (`http://localhost:8001/exams/` / `/exams/${id}`, not `/api/exams`). The gateway (`backend/gateway/main.py`) in fact has **no proxy route at all for `/api/bank-questions`**, so this isn't just an oversight in one file.
  - If you add a new save/fetch call in this feature, match the existing pattern of the file you're editing rather than "fixing" it in isolation — reconciling the two patterns project-wide is a separate, bigger change.
- **`Question` shape is inconsistent between endpoints that both read the same `questions` table.** `GET /bank-questions/` (`backend/exam_service/routes/bank_questions.py`) maps DB rows to the frontend's camelCase `Question` shape (`text`, `correctAnswer`, `type`, `level` as enum strings) — this is what `bankQuestionApi.list()` returns and what `ModalDeRiengLe`/`ModalChonCauHoi`/`ModalSinhDeHoanVi` are built around. But `GET /api/exams` (`backend/exam_service/routes/exams.py::_build_exam_response`) returns raw ORM-shaped `QuestionResponse` for `exam.questions[]` (snake_case `content`/`correct_answer`, opaque `type_id`/`level_id` FKs, **not** the `single/multiple/true_false/short` enum). `ModalDeRiengLe`'s edit-mode init (`exam.questions.filter(q => q.type === ...)`) assumes the camelCase shape — since `exam` there comes from `ExamManagementModule`'s `GET /api/exams`, `q.type` is actually `undefined` on that object. Verify this end-to-end (open "Chỉnh sửa" on an existing exam and check whether questions land in the right part) before relying on edit-mode part-assignment; don't "fix" one side without checking the other endpoint's callers too.
- **The correct, working pattern for "create brand-new questions tied to a brand-new exam" is: `POST /api/exams` with no `questions`/`questionIds` to get a bare exam id, then one `questionApi.create({text, type, level, subject, grade, options, correctAnswer, statements, status, examId})` per question.** `POST /questions/` (backend `questions.py`) fuzzy-matches subject/grade/level/type **by name** server-side (`ILIKE`), so the frontend never has to resolve `type_id`/`level_id`/`subject_id`/`grade_id` itself. `ModalTaoDeTuDong.tsx` (`ai_config` mode) and `ModalSinhDeHoanVi.tsx` both use this pattern correctly. **`ModalAddGoiDeThiNew`'s permutation-exam save is still the old, broken variant** — it POSTs `{questions: [{text, type, level, options, correctAnswer}]}` straight to `/api/exams`, but `ExamCreate.questions` there is typed `List[QuestionBase]`, which requires `content` (not `text`) and snake_case fields; none of the posted keys match, so expect a 422 if that path is ever exercised live. Not yet fixed — if you touch that modal, consider porting it to the `questionApi.create` pattern instead of patching the mismatched keys.
- **`ModalTaoDeTuDong`'s matrix step is fragile against subjects added outside the original 3.** Matrix rows' `subject` column is always one of exactly 3 hardcoded Vietnamese names from `SUBJECT_MAP` in `backend/exam_service/routes/matrix_configs.py` (`mh-toan→"Toán học"`, `mh-ly→"Vật lí"`, `mh-anh→"Tiếng Anh"`), while the Môn học dropdown here is populated from the dynamic `subject_categories` table via `subjectCategoryApi`. A subject added to `subject_categories` beyond those 3 will show zero matrices in that step — this mirrors the same fixed-3-subject limitation already documented in `../quan-ly-ma-tran-de/CLAUDE.md`. Separately, matrix **list-filtering** by subject in `ModalTaoDeTuDong.tsx` (`m.subject === selectedSubject.code || m.subject === selectedSubject.name`) is a case-sensitive exact string match against whatever raw value happens to be stored in `matrix_configs.subject` — in practice this column has been seen holding inconsistent casing/values (`"to"`, `"To"`, `"toan"`, `"Toán học"` all observed for the same subject across different saved matrices), so a matrix genuinely for the right subject can still fail to show up here. Don't assume "zero matrices shown" means "no matrix exists for this subject" without checking the raw `matrix_configs.subject` values directly.
- `../quan-ly-ma-tran-de/mockData.ts` is imported here for `apiGetMatrixConfigDetail`/`MaTranData` — despite its name, that function is a **real** network call (`GET /api/matrix-configs/{id}`), not mock data; only `apiGetMonHoc`/`apiGetChuDe` in that file are genuinely mocked. Don't assume the whole import is inert.
- `ModalDeRiengLe.tsx` hardcodes `grade: 'Khối 12'` on save regardless of subject/topic selection (there's no grade selector in this modal at all) — every manually-built exam is tagged Khối 12 today.
- Backend linking model: `POST/PUT /exams` with `questionIds` does **not** copy/duplicate bank questions — it does `UPDATE questions SET exam_id = ...` (link) and un-linking (`exam_id = NULL`, not delete) for questions removed from an edit. Deleting an exam (`DELETE /exams/{id}`) likewise only un-links its questions, never deletes them from the bank.
- `GET /exams/debug-db` (raw `DESCRIBE questions;`) is an unauthenticated schema-introspection endpoint left in `exams.py` — be aware it exists, don't build on it, and flag it if doing a security pass.
- **`packages` table now has `matrix_id`/`exam_period_id` columns** (nullable `VARCHAR`, added via a direct `ALTER TABLE` migration, no formal migration tool in this repo — `backend/shared/database.py::init_tables()` only runs SQLAlchemy `create_all`, which does **not** add columns to already-existing tables, so any future new column needs the same manual `ALTER TABLE` treatment). These are **label/filter-only** — no FK relationship is declared on the `Package` model, nothing reads them back to filter the list yet, and they don't affect exam-generation logic at all. Set by `ModalSinhDeHoanVi.tsx` from its optional Ma trận đề / Đợt thi dropdowns (both loaded straight from their category APIs — `fetch('/api/matrix-configs?...')` and `examPeriodApi.list()` — with no filtering against the package's own subject beyond a client-side `m.subject === exam.subject` string match, so subject them the same casing caveat as above).

## Commands

Run from the repo root (no separate build for this subfolder):
- `npm run lint` — `tsc --noEmit`, the only fast correctness check available; run this after any edit here.
- `npm run dev` — starts Vite + all Python microservices together (`start_services.py`); needed to actually exercise this feature in the browser, since it depends on the Exam Service (`/exams`, `/packages`, `/bank-questions`, `/matrix-configs`, `/topics`, `/subject-categories`, `/grade-levels`, `/subject-configs`, `/exam-periods`, `/questions`) being up, both via the gateway (port 8000) and directly on port 8001 — and, for `ModalTaoDeTuDong`'s `ai_config` mode, the AI Service (`/api/generate-questions` → port 8002 → Gemini) being reachable and having a non-exhausted `GEMINI_API_KEY` quota.
